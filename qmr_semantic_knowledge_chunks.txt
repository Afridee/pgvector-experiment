title: QMR SQL Template Overview (Must Follow)
tags: topic:overview, applies_to:all, sql_template
content:
You must generate QMR SQL using ONLY these sources/tables:
- monthly_order_cache_YYYY_MM (materialized monthly cache)
- daily_order_cache (live daily cache for current date and later)
No additional joins are allowed in primary/retailer queries.

You must output two queries:
1) primaryDataQuery (required)
2) retailerOrderDataQuery (required; if productType=Total then return: SELECT 1 as "Dummy")

You must follow the date split rules and productType mapping chunks.

Placeholders used in templates:
- {startDate}            : 'YYYY-MM-DD'
- {mvEndDateExclusive}   : 'YYYY-MM-DD' (exclusive upper bound for MV portion)
- {currentDate}          : 'YYYY-MM-DD' (only if current date in range)
- {endDatePlusOne}       : 'YYYY-MM-DD' (exclusive upper bound overall)
- {monthlyTablesSql}     : UNION ALL of per-table monthly SELECTs
- {dailySql}             : daily_order_cache SELECT (only if needed)
- {filtersSql}           : concatenated AND conditions (may be empty)
- {productFieldSql}      : e.g., o.sku_id / o.brand_id / o.family_id / o.segment_id (empty for Total)
- {productSelectSql}     : e.g., o.sku_id AS "sku_id", (empty for Total)
- {productGroupBySql}    : e.g., o.sku_id,  (empty for Total)
- {productDistinctKeySql}: e.g., || '-' || o.sku_id (empty for Total)
- {productFilterSql}     : AND o.sku_id IN (...) depending on productType (empty if no product filter)

IMPORTANT:
- Use >= lower bound and < upper bound (exclusive) for date filtering.
- Memo distinct key is retailer_id + DATE(order_placed_at) + optional product_id.
- Total Memo distinct key is retailer_id + DATE(order_placed_at) only (no product_id).

title: QMR ProductType -> Cache Field Mapping
tags: topic:product_type, applies_to:all, sql_template
content:
Normalize productType into one of: SKU, Brand, Family, Segment, Total.

Mapping (cache column):
- SKU     -> o.sku_id
- Brand   -> o.brand_id
- Family  -> o.family_id
- Segment -> o.segment_id
- Total   -> (no product field)

Template fragments:

If productType != Total:
- {productFieldSql}       = o.<mapped>_id
- {productSelectSql}      = o.<mapped>_id AS "{productIdAlias}",
- {productGroupBySql}     = o.<mapped>_id,
- {productDistinctKeySql} = || '-' || o.<mapped>_id

If productType = Total:
- {productFieldSql}       = (empty)
- {productSelectSql}      = (empty)
- {productGroupBySql}     = (empty)
- {productDistinctKeySql} = (empty)

Product filter fragment (append to WHERE when productFilter is present):
- SKU     -> AND o.sku_id IN ({productIdsCsv})
- Brand   -> AND o.brand_id IN ({productIdsCsv})
- Family  -> AND o.family_id IN ({productIdsCsv})
- Segment -> AND o.segment_id IN ({productIdsCsv})
- Total   -> (optional) AND o.sku_id IN ({productIdsCsv}) only if you explicitly want Total to filter by SKU IDs; otherwise no product filter.
---
title: QMR Date Split Rules (MV vs Daily)
tags: topic:date_split, applies_to:all, sql_template
content:
Given startDate and endDate:
- endDatePlusOne = endDate + 1 day (exclusive upper bound).
- currentDate = today's date.

If startDate <= currentDate <= endDate:
- MV portion uses monthly tables with:
  o.order_placed_at >= '{startDate}' AND o.order_placed_at < '{currentDate}'
- Daily portion uses daily_order_cache with:
  o.order_placed_at >= '{currentDate}' AND o.order_placed_at < '{endDatePlusOne}'

Else:
- Only MV portion:
  o.order_placed_at >= '{startDate}' AND o.order_placed_at < '{endDatePlusOne}'
  and no daily_order_cache query.

Monthly tables list:
monthly_order_cache_{YYYY}_{MM} for each month intersecting the MV portion.

title: QMR Filters Template (Cache WHERE clauses)
tags: topic:filters, applies_to:all, sql_template
content:
Filters are optional and appended as AND clauses.

Each filter is an ID list; ignore if empty or contains "all".

Mapping:
- regionFilter       -> AND o.region_id IN ({regionIdsCsv})
- areaFilter         -> AND o.area_id IN ({areaIdsCsv})
- distributorFilter  -> AND o.house_id IN ({houseIdsCsv})
- territoryFilter    -> AND o.territory_id IN ({territoryIdsCsv})
- pointFilter        -> AND o.point_id IN ({pointIdsCsv})
- subChannelFilter   -> AND o.sub_channel_id IN ({subChannelIdsCsv})
- productFilter      -> use ProductType mapping chunk to choose AND o.<field> IN ({productIdsCsv})

Combine into:
{filtersSql} = (zero or more lines, each starting with AND ...)

title: QMR Primary Query Template (Per-Table SELECT)
tags: topic:primary_query, applies_to:all, sql_template
content:
Per-table SELECT template. Use this for BOTH monthly_order_cache_* tables and daily_order_cache (with different date bounds).

```sql
SELECT
  o.point_id AS "pointId",
  o.retailer_code AS "Retailer Code",
  o.retailer_name AS "Retailer Name",
  o.sub_channel_id AS "SubChannelId",
  o.cluster_id AS "ClusterId",
  o.tpg_id AS "TpgId",
  o.original_route_section_id AS "RouteSectionId",
  {productSelectSql}
  COUNT(
    DISTINCT
      o.retailer_id || '-' || DATE(o.order_placed_at) {productDistinctKeySql}
  )::INT4 AS "Memo",
  SUM(o.total_stt) AS "STT"
FROM {tableName} o
WHERE
  o.order_placed_at >= '{dateLowerInclusive}'
  AND o.order_placed_at < '{dateUpperExclusive}'
  {filtersSql}
  {productFilterSql}
GROUP BY
  {productGroupBySql}
  o.point_id,
  o.retailer_code,
  o.retailer_name,
  o.sub_channel_id,
  o.cluster_id,
  o.tpg_id,
  o.original_route_section_id
```

Notes:
- {productSelectSql}, {productGroupBySql}, {productDistinctKeySql} are empty for Total.
- {filtersSql} should already include leading ANDs; if empty, remove blank lines.

title: QMR Primary Query Template (Union + Outer Aggregate)
tags: topic:primary_query_outer, applies_to:all, sql_template
content:
After generating per-table primary SELECTs, UNION ALL them, then aggregate:

If productType != Total:

```sql
SELECT
  "pointId",
  "Retailer Code",
  "Retailer Name",
  "SubChannelId",
  "ClusterId",
  "TpgId",
  "RouteSectionId",
  "{productIdAlias}",
  SUM("Memo")::INT4 AS "Memo",
  SUM("STT") AS "STT"
FROM (
  {unionAllPrimarySelects}
) combined
GROUP BY
  "{productIdAlias}",
  "pointId",
  "Retailer Code",
  "Retailer Name",
  "SubChannelId",
  "ClusterId",
  "TpgId",
  "RouteSectionId"
ORDER BY "pointId"
```

If productType = Total:

```sql
SELECT
  "pointId",
  "Retailer Code",
  "Retailer Name",
  "SubChannelId",
  "ClusterId",
  "TpgId",
  "RouteSectionId",
  SUM("Memo")::INT4 AS "Memo",
  SUM("STT") AS "STT"
FROM (
  {unionAllPrimarySelects}
) combined
GROUP BY
  "pointId",
  "Retailer Code",
  "Retailer Name",
  "SubChannelId",
  "ClusterId",
  "TpgId",
  "RouteSectionId"
ORDER BY "pointId"
```

title: QMR Retailer Order Query Template (Per-Table SELECT)
tags: topic:retailer_query, applies_to:sku, applies_to:brand, applies_to:family, applies_to:segment, sql_template
content:
Only generate this query when productType != Total.

Per-table SELECT template:

```sql
SELECT
  o.point_id AS "pointId",
  o.retailer_code AS "Retailer Code",
  o.original_route_section_id AS "RouteSectionId",
  COUNT(DISTINCT o.retailer_id || '-' || DATE(o.order_placed_at))::INT4 AS "Total Memo"
FROM {tableName} o
WHERE
  o.order_placed_at >= '{dateLowerInclusive}'
  AND o.order_placed_at < '{dateUpperExclusive}'
  {filtersSql}
  {productFilterSql}
GROUP BY
  o.point_id,
  o.retailer_code,
  o.original_route_section_id
```

Note:
- Do NOT include productDistinctKeySql here. Total Memo is retailer_id+date only.
