title: QMR SQL Template Overview (Must Follow)
tags: topic:overview, applies_to:all, sql_template
content:
You must generate QMR SQL using ONLY these yearly tables:
- raw_apsis_qmr_data_2022
- raw_apsis_qmr_data_2023
- raw_apsis_qmr_data_2024
- raw_apsis_qmr_data_2025

There is NO daily cache table and NO monthly partitioned table. All data including recent dates
comes from the yearly raw_apsis_qmr_data_YYYY tables. No additional joins are allowed.

Each row is already pre-aggregated (one row per retailer per SKU per extracted_date).
Do NOT use COUNT(DISTINCT ...) for Memo — use SUM(o.memo_value::numeric) instead.
Do NOT use COUNT(DISTINCT ...) for STT  — use SUM(o.stt_value::numeric) instead.

You must output two queries:
1) primaryDataQuery (required)
2) retailerOrderDataQuery (required; if productType=Total then return: SELECT 1 as "Dummy")

Table columns (all VARCHAR unless noted):
- region, area, house (distributor), territory, point, route_section
- retailer_code, retailer_name, cluster, cluster_type, tpg, sub_channel, channel
- sku              : SKU name — the ONLY product dimension available
- stt_value        : pre-aggregated STT  (cast: stt_value::numeric)
- memo_value       : pre-aggregated Memo (cast: memo_value::numeric)
- extracted_date   : date string in 'YYYY-MM-DD' format — use string comparison for filtering

IMPORTANT:
- Use >= lower bound and < upper bound (exclusive) for date filtering on extracted_date.
- extracted_date is VARCHAR in ISO format — string comparison (>=, <) is correct.
- All filters are NAME-based (text), NOT id-based.
- Only SKU and Total product types are supported (no brand/family/segment columns exist).

title: QMR Year Table Selection Rules
tags: topic:date_split, applies_to:all, sql_template
content:
Given startDate and endDate:
- endDatePlusOne = endDate + 1 day (exclusive upper bound).
- Select ALL yearly tables whose year intersects the date range.

Available tables and their year coverage:
- raw_apsis_qmr_data_2022  (year 2022)
- raw_apsis_qmr_data_2023  (year 2023)
- raw_apsis_qmr_data_2024  (year 2024)
- raw_apsis_qmr_data_2025  (year 2025)

For each selected table, apply the FULL date range filter:
  o.extracted_date >= '{startDate}' AND o.extracted_date < '{endDatePlusOne}'

The yearly table itself limits data to its year naturally — no extra year filter needed.

Example: startDate=2024-10-01, endDate=2025-03-31
- endDatePlusOne = 2025-04-01
- Use raw_apsis_qmr_data_2024 WITH: extracted_date >= '2024-10-01' AND extracted_date < '2025-04-01'
- Use raw_apsis_qmr_data_2025 WITH: extracted_date >= '2024-10-01' AND extracted_date < '2025-04-01'
- UNION ALL both, then aggregate in outer query.

There is NO daily cache and NO current-date split logic needed.

title: QMR ProductType Mapping
tags: topic:product_type, applies_to:all, sql_template
content:
Only two product types are supported (the table only has a sku text column):
- SKU   -> group by o.sku, include in SELECT
- Total -> no product grouping (aggregate across all SKUs)

If productType = SKU:
- {productSelectSql}  = o.sku AS "SKU",
- {productGroupBySql} = o.sku,
- {productFilterSql}  = AND o.sku IN ({skuNamesCsv})   [only if skuFilter provided; values are text names]

If productType = Total:
- {productSelectSql}  = (empty)
- {productGroupBySql} = (empty)
- {productFilterSql}  = (empty)

Note: productFilter values are SKU NAMES (text strings), not numeric IDs.

title: QMR Filters Template
tags: topic:filters, applies_to:all, sql_template
content:
Filters are optional AND clauses. ALL filters use TEXT/NAME matching — not IDs.

Each filter is a name list; ignore if empty or contains "all".

Mapping:
- regionFilter      -> AND o.region IN ({regionNamesCsv})
- areaFilter        -> AND o.area IN ({areaNamesCsv})
- distributorFilter -> AND o.house IN ({houseNamesCsv})
- territoryFilter   -> AND o.territory IN ({territoryNamesCsv})
- pointFilter       -> AND o.point IN ({pointNamesCsv})
- subChannelFilter  -> AND o.sub_channel IN ({subChannelNamesCsv})
- skuFilter         -> AND o.sku IN ({skuNamesCsv})  [only when productType=SKU]

Values must be quoted strings in SQL, e.g.: AND o.region IN ('Dhaka', 'Rajshahi')

Combine into {filtersSql} = (zero or more lines, each starting with AND ...).

title: QMR Primary Query Template (Per-Table SELECT)
tags: topic:primary_query, applies_to:all, sql_template
content:
Per-table SELECT for raw_apsis_qmr_data_YYYY. Data is pre-aggregated — use SUM, not COUNT(DISTINCT).

```sql
SELECT
  o.point AS "Point",
  o.retailer_code AS "Retailer Code",
  o.retailer_name AS "Retailer Name",
  o.sub_channel AS "SubChannel",
  o.cluster AS "Cluster",
  o.tpg AS "TPG",
  o.route_section AS "RouteSection",
  {productSelectSql}
  SUM(o.memo_value::numeric)::INT4 AS "Memo",
  SUM(o.stt_value::numeric) AS "STT"
FROM {tableName} o
WHERE
  o.extracted_date >= '{startDate}'
  AND o.extracted_date < '{endDatePlusOne}'
  {filtersSql}
  {productFilterSql}
GROUP BY
  {productGroupBySql}
  o.point,
  o.retailer_code,
  o.retailer_name,
  o.sub_channel,
  o.cluster,
  o.tpg,
  o.route_section
```

Notes:
- {productSelectSql} and {productGroupBySql} are empty for Total.
- {filtersSql} includes leading ANDs; remove blank lines if empty.
- extracted_date is VARCHAR ISO format; string comparison >= and < is safe.

title: QMR Retailer Order Query Template (Per-Table SELECT)
tags: topic:retailer_query, applies_to:sku, sql_template
content:
Only generate this query when productType = SKU.

This computes Total Memo at retailer level (ignoring SKU). Since rows are pre-aggregated per SKU,
use COUNT(DISTINCT retailer_code || '-' || extracted_date) to avoid double-counting.
Do NOT apply skuFilter here — Total Memo is across all SKUs.

```sql
SELECT
  o.point AS "Point",
  o.retailer_code AS "Retailer Code",
  o.route_section AS "RouteSection",
  COUNT(DISTINCT o.retailer_code || '-' || o.extracted_date)::INT4 AS "Total Memo"
FROM {tableName} o
WHERE
  o.extracted_date >= '{startDate}'
  AND o.extracted_date < '{endDatePlusOne}'
  {filtersSql}
GROUP BY
  o.point,
  o.retailer_code,
  o.route_section
```
