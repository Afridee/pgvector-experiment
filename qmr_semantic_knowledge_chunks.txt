---
title: API Overview — JSONPlaceholder Base URL and Available Resources
tags: topic:overview, applies_to:all
content:
This knowledge base documents the JSONPlaceholder API — a free live REST API
available at:

  https://jsonplaceholder.typicode.com

No authentication is required. Do NOT send any Authorization header.

Available resources and their base endpoints:
- Posts    → /posts
- Comments → /comments
- Albums   → /albums
- Photos   → /photos
- Todos    → /todos
- Users    → /users

Nested resource endpoints (also supported):
- /posts/{postId}/comments     → comments belonging to a post
- /albums/{albumId}/photos     → photos belonging to an album
- /users/{userId}/posts        → posts created by a user
- /users/{userId}/albums       → albums created by a user
- /users/{userId}/todos        → todos belonging to a user

All responses are JSON. POST/PUT/PATCH/DELETE calls are simulated —
the API responds realistically but does not persist changes. This is expected.

Always present data in readable tables or summaries. Never dump raw JSON
at the user unless they explicitly ask for it.

---
title: API General Error Handling
tags: topic:errors, applies_to:all, edge_case
content:
Handle these HTTP error codes for ALL endpoints:

HTTP 404 — Not Found:
  The resource does not exist at that ID.
  Tell the user: "No record found with that ID. Please check and try again."
  Valid ranges: post_id 1–100, user_id 1–10, album_id 1–100,
                photo_id 1–5000, todo_id 1–200, comment_id 1–500.

HTTP 400 — Bad Request:
  The request body or parameters are malformed.
  Tell the user what field looks wrong and ask them to correct it.

HTTP 500 — Server Error:
  Tell the user: "The API is currently unavailable. Please try again shortly."

For any error, do NOT retry automatically. Always inform the user first.

If the user provides an ID outside the valid range, warn them BEFORE calling:
  "Post IDs range from 1 to 100. Please provide a valid ID."

---
title: API Parameter Validation Rules
tags: topic:validation, applies_to:all, business_rule
content:
Apply these rules before calling any endpoint:

ID field valid ranges:
- post_id    : integer, 1 to 100
- user_id    : integer, 1 to 10
- album_id   : integer, 1 to 100
- photo_id   : integer, 1 to 5000
- todo_id    : integer, 1 to 200
- comment_id : integer, 1 to 500

Rules:
- All IDs must be positive integers. If the user provides a non-integer, ask
  them to correct it.
- If an ID is outside the valid range, warn the user before making the call.
- String fields (title, body, name) must not be empty. Ask the user to provide
  content if they are empty.
- userId in POST bodies must be an integer between 1 and 10.
- Do NOT use placeholder or assumed values for any required parameter.
  Always ask the user explicitly if something is missing.

---
title: Fetch All Posts — Endpoint and Method
tags: topic:endpoint, applies_to:posts, api_template
content:
To fetch all posts, make a GET request to:

  https://jsonplaceholder.typicode.com/posts

No parameters or payload required.
No required information to collect from the user before calling.
---

---
title: Fetch All Posts — Optional Parameters
tags: topic:parameters, applies_to:posts
content:
The following optional query parameter can be used to filter posts by user:

- userId : integer (1–10) — return only posts created by this user.

Only include this parameter if the user explicitly asks to filter by a user.
Example URL with filter: https://jsonplaceholder.typicode.com/posts?userId=1

Do NOT prompt the user for this. Only use it if they mention a specific user.
