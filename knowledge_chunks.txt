title: Checklist Record API — Response Extraction and Pagination Guide
tags: topic:response, topic:extraction, applies_to:checklist_record
content:
You must treat RECORD.checklistReadings as a potentially long list and ALWAYS paginate it inside the extraction_script. Do NOT rely on api_call's list pagination for this endpoint; instead, the extraction_script itself must return only one page of readings plus explicit paginationInfo.

DEFAULT EXTRACTION RULE:
- When the user asks for a checklist report (to view or summarise checklist readings), you MUST:
  - Use an extraction_script that:
    - Reads the full RECORD object from response["RECORD"].
    - Slices RECORD.checklistReadings to only the current page.
    - Returns a single object containing: date, venueName, submitted, readings (paged), and paginationInfo.
  - On the first call, hard-code offset=0 and limit=20 inside the extraction_script unless the user explicitly asks for a different page size.
  - On follow-up calls, update the offset literal in the extraction_script to the next page's starting index (e.g. 20, 40, 60, ...).

Recommended extraction_script (first page, offset 0, limit 20):

```python
limit = 20          # page size; change only if the user asks
offset = 0          # currentOffset for this call; update to 20, 40, ... for later pages

record = (response or {}).get("RECORD") or {}
if not record:
    result = {"message": "No checklist record found for the specified date."}
else:
    all_readings = record.get("checklistReadings") or []
    paged = all_readings[offset: offset + limit]

    result = {
        "date": record.get("date"),
        "venueName": (record.get("elementsVenue") or {}).get("venueName"),
        "submitted": record.get("submitted"),
        "readings": [
            {
                "criteria_name": (r.get("checklistCriteria") or {}).get("name"),
                "checked": r.get("checked"),
                "comment": r.get("comment"),
            }
            for r in paged
        ],
        "paginationInfo": {
            "limit": limit,
            "currentOffset": offset,
        },
    }
```

Pagination behaviour:
- The extraction_script MUST:
  - Return at most limit readings in the readings array.
  - Include paginationInfo.limit and paginationInfo.currentOffset so the UI can track state.
- On the first call:
  - Use offset = 0 and limit = 20 unless the user has requested a different size.
- When the user asks for "more" readings:
  - Call the same endpoint again with a new extraction_script where:
    - offset is increased by limit (e.g. 20, 40, 60, ...).
    - limit stays the same, unless the user changes it.

How to present results:
- When showing checklist readings to the user:
  - Use paginationInfo.limit and paginationInfo.currentOffset to compute the item range, e.g. "Showing 1–20 checklist readings (page 1)".
  - Display readings as a table or bullet list including at least:
    - criteria_name
    - checked
    - comment (if present)
  - After showing a page, ask the user if they want to see more when the length of readings equals paginationInfo.limit.

Important notes:
- Do NOT return the full RECORD object when the user only needs readings; always use the paged result structure above.
- For this endpoint, you SHOULD NOT use api_call's list_limit/list_offset pagination, because pagination is handled inside the extraction_script with paginationInfo.
- Never auto-fetch all pages unless the user explicitly asks for all checklist readings.
