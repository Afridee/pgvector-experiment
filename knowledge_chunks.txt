title: Authentication — Required Headers for All Endpoints
tags: topic:auth, applies_to:all
content:
Every request to every report endpoint MUST include the following three headers.
You MUST inject these from the session/environment — do NOT ask the user for them.

  Authorization: Bearer {access_token}
  x-refresh-token: {refresh_token}
  x-validate-token: {validate_token}

If any of these tokens are missing from the session context, inform the user that they need to log in first.
Do NOT use placeholder values. Do NOT hard-code any token values.

title: SSS Report API — Endpoint and Method
tags: topic:endpoint, applies_to:sss_report, api_template
content:
To generate an SSS (Sales Summary Sheet) report, make a GET request to:

  {BASE_URL}/reports/sss-report

The base URL is environment-specific. Read it from the BASE_URL environment variable.
Do NOT hard-code the base URL.
You MUST include the authentication headers described in "Authentication — Required Headers for All Endpoints".

Example request URL:

  GET {BASE_URL}/reports/sss-report?date=2025-06-15&ffType=2&pointFilter[]=1&pointFilter[]=2
---

---
title: SSS Report API — Required Parameters
tags: topic:parameters, applies_to:sss_report, business_rule
content:
Before calling the SSS Report API, you MUST collect ALL of the following from the user:

- date : string in YYYY-MM-DD format — the specific date for the report
- ffType : integer — the field force role type ID. Valid values: 2 (SR), 3 (SS), 4 (SM)
- pointFilter[] : array of integers — one or more point IDs to filter by

All three parameters are required. If ANY are missing, ask the user before calling the API.
Do NOT use placeholder or default values.

These are sent as query string parameters. Because pointFilter is an array, repeat the key for each value:
  ?date=2025-06-15&ffType=2&pointFilter[]=1&pointFilter[]=2

---
title: SSS Report API — Response Structure and Extraction Guide
tags: topic:response, applies_to:sss_report, extraction
content:
A successful SSS Report API response (HTTP 200) has this top-level shape:

  {
    "status": 200,
    "message": "SSS report fetched successfully",
    "data": {
      "outerData": [...],   // sub-channel summary rows
      "innerData": [...],   // per-route/FF detail rows
      "subChannels": [...], // list of sub-channel names present
      "allSkus": [...],     // list of all SKU names present
      "summation": {...}    // overall totals
    }
  }

outerData — array of sub-channel summary objects. Each has:
  - type : string — sub-channel name e.g. "Silver STT", "Total Memo", "total STT"
  - data : object — keys are SKU names with numeric string values, plus "user_name", "route_name", "no_of_memo"
  Sub-channel types: Silver STT, Platinum STT, RCC STT, Gold STT, GT STT, BCC STT, TRC STT, total STT, Total Memo

innerData — array of per-route detail objects. Each row has:
  - route_id, route_name
  - user_name, user_id
  - no_of_memo           : integer
  - total_volume         : numeric string (HL)
  - total_value          : numeric string (BDT)
  - total_discount, net_value, unnoti_reimbursement : numeric strings
  - targeted_outlet      : integer
  - percentage_of_value, percentage_of_volume : numeric strings
  - <SKU name>           : numeric string — one key per SKU (e.g. "B&H SF 20HL", "LS OG 20HL PUG")

summation — overall totals:
  - totalMemo, totalTargetedOutlet : integers
  - totalValue, totalVolume, totalDiscount, totalNetValue, totalUnnotiReimbursement : numeric strings

ALWAYS use an extraction_script when calling the SSS Report API.
The raw response is ~60,000 chars — far above the 12,000-char tool output limit.
Without an extraction_script, most data will be silently truncated.

Example extraction scripts:

1. Overall summary only:
   result = response.get("data", {}).get("summation", {})

2. Per-route table (innerData), key columns only:
   rows = response.get("data", {}).get("innerData", [])
   result = [{"route": r.get("route_name"), "ff": r.get("user_name"), "memos": r.get("no_of_memo"), "volume": r.get("total_volume"), "value": r.get("total_value"), "net_value": r.get("net_value"), "outlets": r.get("targeted_outlet")} for r in rows]

3. Sub-channel summary (outerData):
   result = [{"sub_channel": item.get("type"), "data": item.get("data", {})} for item in response.get("data", {}).get("outerData", [])]

4. Total STT and Memo rows only:
   outer = response.get("data", {}).get("outerData", [])
   result = [x for x in outer if x.get("type") in ("total STT", "Total Memo")]

DEFAULT EXTRACTION RULE — follow this unless told otherwise:
Use script 1 (summation) for any general request. This includes prompts like:
  "SSS report for <date>", "generate the report", "show the report", or any request
  that does not explicitly mention routes, sub-channels, or STT vs Memo.
Only use scripts 2–4 when the user explicitly asks for that level of detail.

This endpoint returns structured JSON — it does NOT generate a downloadable file.
If status is not 200, or if "data" is empty or missing, inform the user that no data was found.

title: Query Manager Report API — Endpoint and Method
tags: topic:endpoint, applies_to:query_manager_report, api_template
content:
To generate a Query Manager Report (QMR), make a POST request to:

  {BASE_URL}/reports/query-manager-report

The base URL is environment-specific. Read it from the BASE_URL environment variable.
Do NOT hard-code the base URL.
You MUST include:
  Content-Type: application/json
  Authorization: Bearer {access_token}
  x-refresh-token: {refresh_token}
  x-validate-token: {validate_token}

Example request:

```json
{
  "startDate": "2026-01-08",
  "endDate": "2026-01-08",
  "regionFilter": [1, 2, 3],
  "subChannelFilter": [1, 2, 3],
  "productFilter": [1, 2, 14],
  "productType": "total",
  "reportType": ["stt", "memo"],
  "activeStatus": ["current"],
  "sttCriteria": { "sign": ">", "number": 0 },
  "memoCriteria": { "sign": ">", "number": 0 }
}
```
---

---
title: Query Manager Report API — Required Parameters
tags: topic:parameters, applies_to:query_manager_report, business_rule
content:
Before calling the Query Manager Report API, you MUST collect ALL of the following from the user:

- startDate : string in YYYY-MM-DD format — start of the reporting period
- endDate : string in YYYY-MM-DD format — end of the reporting period (inclusive)
- regionFilter : array of integers — one or more region IDs
- subChannelFilter : array of integers — one or more sub-channel IDs
- productFilter : array of integers — one or more product IDs
- productType : string — one of: "total", "sku", "brand", "family", "segment"
- reportType : array of strings — one or both of: "stt", "memo"

If ANY of these are missing, ask the user before calling the API.
Do NOT use placeholder or default values.
---

---
title: Query Manager Report API — Optional Parameters
tags: topic:parameters, applies_to:query_manager_report
content:
The following fields are optional for the Query Manager Report API:

- activeStatus : array of strings — filter by retailer active status. Use ["current"] for active retailers, ["inactive"] for inactive, or omit to include all.
- sttCriteria : object — filter rows by STT value. Shape: { "sign": ">"|"<"|">="|"<="|"=", "number": <integer> }. Default behaviour is no filter.
- memoCriteria : object — filter rows by memo count. Shape: { "sign": ">"|"<"|">="|"<="|"=", "number": <integer> }. Default behaviour is no filter.
- requestId : string — a UUID to track the report request; used for email notification. Can be omitted for direct calls.
---

tags: topic:response, applies_to:query_manager_report
content:

```json
  "message": "QMR report generated successfully",
  "data": {
    "fileUrl": "https://<azure-blob-url>/reports/<requestId>/<filename>.xlsx",
```

and show the error message from the response.

```json
{
  "status": 404,
  "message": "No data found for the given query",
  "data": {}
}
```
