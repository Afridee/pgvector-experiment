Purpose:

- Query params: staffId
---

---
title: Clocking Check Status API — Required Parameters
tags: topic:parameters, applies_to:clocking_check_status, business_rule
content:
Before calling this endpoint, you MUST have the following value:

- staffId : string — the ID of the staff member to check

Example URL:
  https://api-ebg-erp.binarycraftbd.com/api/clocking/record/checkClockingStatus?staffId=54
---

---
title: Clocking Check Status API — Response
tags: topic:response, applies_to:clocking_check_status
content:
A successful response (HTTP 200) returns a JSON object.

When the staff member is NOT currently clocked in:
```json
{
  "RESPONSE": "CLOCK_IN_NOT_RUNNING"
}
```

When the staff member IS currently clocked in:
```json
{
  "RESPONSE": "CLOCK_IN_RUNNING",
  "CLOCKING_RECORD_ID": 101,
  "WORK_DURATION": "03:45",
  "CLOCK_IN_TIME": "09:00",
  "CLOCK_IN_DATE": "2025-01-06"
}
```

Important field paths:
- RESPONSE            — string, either "CLOCK_IN_NOT_RUNNING" or another value indicating active session
- CLOCKING_RECORD_ID  — integer, present only when clock-in is active
- WORK_DURATION       — string (HH:mm), present only when clock-in is active
- CLOCK_IN_TIME       — string, present only when clock-in is active
- CLOCK_IN_DATE       — string (YYYY-MM-DD), present only when clock-in is active

If RESPONSE == "CLOCK_IN_NOT_RUNNING", the staff member is not currently clocked in.
Otherwise, a session is active and the fields above will be populated.

---
title: Training Subject API — Endpoint and Method
tags: topic:endpoint, applies_to:training_subject, api_template
content:
Purpose:
- Returns the training subject record for a given training station and training type combination. A training subject links a station to a specific type of training programme.

Endpoint:
- Method: GET
- URL: https://api-ebg-erp.binarycraftbd.com/api/e360/training/trainingSubject
- Query params: stationId, trainingType
---

---
title: Training Subject API — Required Parameters
tags: topic:parameters, applies_to:training_subject, business_rule
content:
Before calling this endpoint, you MUST have BOTH of the following:

- stationId    : integer — the training station ID
- trainingType : string  — the type of training programme. Known values used in the app:
    "INITIAL_TRAINING"      — first-time training for a new staff member at a station
    "TRAINING_VERIFICATION" — follow-up verification of previously completed training

Example URL:
  https://api-ebg-erp.binarycraftbd.com/api/e360/training/trainingSubject?stationId=2&trainingType=INITIAL_TRAINING

If either value is missing, ask the user before calling.
---

---
title: Training Subject API — Response
tags: topic:response, applies_to:training_subject
content:
A successful response (HTTP 200) returns a single JSON object representing the training subject.

Response structure:
```json
{
  "id": 5,
  "trainingType": "INITIAL_TRAINING",
  "trainingStation": {
    "id": 2,
    "name": "Coffee Bar"
  }
}
```

Important field paths:
- id                        — integer, unique training subject ID (use this as trainingSubjectId for the criteria list API)
- trainingType              — string
- trainingStation.id
- trainingStation.name

If the response is null or empty, inform the user that no training subject exists for the given station and training type combination.

title: Breakage Report by Venue and Date API — Endpoint and Method
tags: topic:endpoint, applies_to:breakage_report, api_template
content:
Purpose:
- Fetches an existing breakage/glassware report for a specific date and venue.

Endpoint:
- Method: GET
- URL: https://api-ebg-erp.binarycraftbd.com/api/breakageReport/reportByVenueAndDate
- Query params: date, venue
---

---
title: Breakage Report by Venue and Date API — Required Parameters
tags: topic:parameters, applies_to:breakage_report, business_rule
content:
Before calling this endpoint, you MUST have BOTH of the following:

- date  : string in YYYY-MM-DD format — the date of the report
- venue : string — the venue name (NOT the venue ID; this is the venue name string)

Example URL:
  https://api-ebg-erp.binarycraftbd.com/api/breakageReport/reportByVenueAndDate?date=2025-01-06&venue=Bistro

If either is missing, ask the user before calling.
---

---
title: Breakage Report by Venue and Date API — Response
tags: topic:response, applies_to:breakage_report
content:
A successful response (HTTP 200) returns a JSON object with a RESPONSE discriminator.

When a report EXISTS:
```json
{
  "RESPONSE": "REPORT_EXISTS",
  "REPORT": {
    "id": 40,
    "venue": "Bistro",
    "date": "2025-01-06",
    "day": "Monday",
    "submittedByStaff": { "id": 54, "firstName": "John", ... },
    "finalized": true,
    "netSales": 5200.00,
    "totalBreakageCost": 45.50,
    "totalBreakagePercentage": 0.87,
    "breakageDetails": [
      {
        "id": 500,
        "qty": 2,
        "totalCost": 15.00,
        "reason": "Accidental drop",
        "glasswareItem": {
          "id": 8,
          "name": "Wine Glass",
          "size": "250ml",
          "type": "Glass",
          "unitCost": 7.50,
          "imageUrl": "https://..."
        }
      }
    ]
  }
}
```

When NO report is found, RESPONSE will NOT equal "REPORT_EXISTS" and REPORT will be absent. Inform the user that no breakage report exists for the given date and venue.

Important field paths:
- RESPONSE
- REPORT.id
- REPORT.venue
- REPORT.date
- REPORT.day
- REPORT.finalized                    — boolean; a finalised report cannot be edited
- REPORT.netSales                     — double
- REPORT.totalBreakageCost            — double
- REPORT.totalBreakagePercentage      — double
- REPORT.submittedByStaff.firstName
- REPORT.breakageDetails[*].qty
- REPORT.breakageDetails[*].totalCost
- REPORT.breakageDetails[*].reason
- REPORT.breakageDetails[*].glasswareItem.name
- REPORT.breakageDetails[*].glasswareItem.unitCost

title: Get All Enrolments API — Endpoint and Method
tags: topic:endpoint, applies_to:get_all_enrolments, api_template
content:
To retrieve all staff enrolments, make a GET request to:

  https://api-ebg-erp.binarycraftbd.com/api/e360/enrolment/getAllEnrolments

HTTP Method: GET
No request body is required.
No query parameters are required.

The response is a JSON array. Each element is a staff enrolment object.
Use the staff.id field from each enrolment when calling the clock-in or clock-out APIs.
---
---
title: Get All Enrolments API — Parameters
tags: topic:parameters, applies_to:get_all_enrolments
content:
This endpoint requires NO parameters — no query params, no path params, no request body.

Do NOT ask the user for any input before calling this endpoint.
Call it directly when the user asks to fetch, list, or refresh all staff enrolments.
---

tags: topic:response, applies_to:get_all_enrolments
content:
A successful response (HTTP 200) is a JSON array of staff enrolment objects.

Example (single element shown):

```json
[
  {
    "id": 42,
    "givenNames": "Jane",
    "surname": "Doe",
    "dob": "1990-05-15",
    "address": "12 Main Street",
    "postCode": "2000",
    "homePhoneNumber": "0291234567",
    "mobileNumber": "0412345678",
    "email": "jane.doe@example.com",
    "nextOfKinName": "John Doe",
    "nextOfKinPhone": "0411111111",
    "defaultSite": {
      "id": 3,
      "name": "Sydney HQ"
    },
    "personalPhotoFiles": [
      { "id": 101, "url": "https://..." }
    ],
    "staff": {
      "id": 7,
      "firstName": "Jane",
      "middleName": null,
      "lastName": "Doe",
      "dob": "1990-05-15",
      "address": "12 Main Street",
      "postCode": "2000",
      "suburb": "Sydney",
      "phoneNumber": "0412345678",
      "enrolmentSubmitted": true,
      "enrolmentCompleted": true,
      "accessProhibited": false,
      "terminated": false,
      "authUser": {
        "id": 55,
        "username": "jane.doe"
      },
      "staffPermissions": []
    },
    "staffDepartment": {
      "id": 2,
      "name": "Front of House"
    }
  }
]
```

Important field paths (per array element):
- [*].id                          — enrolment record ID
- [*].givenNames                  — staff given/first name(s)
- [*].surname                     — staff surname
- [*].dob                         — date of birth (string)
- [*].email                       — staff email
- [*].mobileNumber                — mobile phone number
- [*].defaultSite.id              — default site ID (use as siteId in clock-in/out calls)
- [*].defaultSite.name            — default site name
- [*].personalPhotoFiles[0].url   — URL of the staff's profile photo
- [*].staff.id                    — staff ID (REQUIRED for clock-in, clock-out, image upload, access code APIs)
- [*].staff.firstName             — staff first name (from staff sub-object)
- [*].staff.lastName              — staff last name
- [*].staff.enrolmentSubmitted    — boolean; whether enrolment has been submitted
- [*].staff.enrolmentCompleted    — boolean; whether enrolment is fully completed
- [*].staff.accessProhibited      — boolean; if true, staff cannot clock in
- [*].staff.terminated            — boolean; if true, staff is no longer active
- [*].staff.authUser.id           — auth user ID
- [*].staff.authUser.username     — login username
- [*].staffDepartment.id          — department ID
- [*].staffDepartment.name        — department name

If the array is empty, inform the user that no enrolments were found.
If the request fails (non-200), show the HTTP status code and any error message returned.
